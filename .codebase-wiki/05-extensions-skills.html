05 · Extensions and Skills

Pi is designed to be customized without forking core

Skills change what the model knows. Extensions change what Pi can do. Prompt templates change what users can quickly ask. Pi packages distribute those pieces.

Key files. Skill loading is in skills.ts. Extension capabilities are typed in extensions/types.ts. System prompt assembly is in system-prompt.ts.
skills

Instruction packs

A skill is discovered from SKILL.md frontmatter and content. Skills are added to the prompt so the model knows when and how to apply specialized behavior.

extensions

Runtime hooks

Extensions can register tools, commands, UI, shortcuts, provider hooks, lifecycle handlers, and session entries.

templates

Reusable prompts

Prompt templates expand user input into repeatable prompts without changing the runtime.

packages

Distribution

Packages bundle skills, extensions, themes, and prompts so users can share workflows through npm, git, or local paths.

What a skill does

loadSkillsFromDir looks for SKILL.md, validates frontmatter like name and description, records source info, and later formatSkillsForPrompt makes those skills available to the model. A skill is mostly prompt-level behavior.

---
name: html-over-markdown
description: Generate rich, self-contained HTML documents...
---

# HTML Over Markdown
Instructions the model should follow when this skill applies.

What an extension can do

The extension type surface is much broader than skills. It includes UI dialogs, widgets, terminal input handling, custom tools, lifecycle events, slash commands, model/provider hooks, custom session entries, and compaction hooks. Use extensions when behavior requires code, not just instructions.

Beginner distinction

If you want the model to know a workflow, write a skill. If you want Pi to perform a new operation, write an extension or tool. If you want a repeatable user command, add a prompt template or slash command.
