04 · Sessions and Context

Pi has to remember, but models only see a selected context

A session is the durable record. Context is the model-facing slice produced from that record. Keeping those separate is how Pi supports branches, compaction, hidden extension state, and custom message conversion.

Key files. Session storage is in session-manager.ts. Message conversion is in messages.ts. Compaction lives under core/compaction.

Session entries

JSONL entries include messages, model changes, thinking-level changes, compactions, branch summaries, labels, session info, and extension custom entries.

Message tree

Each entry has id and parentId. That makes branch and tree features possible without copying a whole session file per fork.

Model context

buildSessionContext and convertToLlm decide what the provider sees. UI-only or extension-only state can stay out of the LLM request.

Custom messages become model-readable text

Pi extends the base agent messages with coding-agent-specific roles. For example, a bashExecution message from !command becomes a user message unless it was created with !! and marked excludeFromContext.

bashExecution -> user message with command and output
custom        -> user message if injected by extension
branchSummary -> user message wrapped in summary tags
compactionSummary -> user message wrapped in summary tags
user/assistant/toolResult -> pass through

Why compaction exists

Models have finite context windows. Pi can summarize older history into a compactionSummary while keeping recent messages. The session record still has the durable history, but the model gets a shorter working context.
