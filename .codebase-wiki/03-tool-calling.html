03 · Tool Calling

Tools are how the model touches the world

Pi exposes tools as typed definitions. The model chooses a tool and arguments; Pi validates the call, runs local code, and returns a tool-result message.

Key file. Tool batching is in agent-loop.ts. Built-in coding tools are created from core/tools/index.ts.
read

read.ts reads text and images, truncates large text, and can resize image inputs.

bash

bash.ts spawns a shell, streams output updates, handles aborts, and kills process trees.

edit/write

edit.ts and write.ts mutate files through controlled tool definitions.

grep/find/ls

Read-only exploration tools give the model cheaper, narrower ways to inspect a project.

Sequential vs parallel

The loop defaults toward parallel execution for a batch, but a global setting or a tool marked executionMode: "sequential" can force one-at-a-time execution. Preparation still happens before execution, so invalid arguments or blocked calls become immediate error results.

executeToolCalls(...)
  if config.toolExecution === "sequential" or any tool is sequential:
    executeToolCallsSequential(...)
  else:
    executeToolCallsParallel(...)

What to notice in the source

prepareToolCall finds the tool, prepares arguments, validates schema, and runs beforeToolCall. executePreparedToolCall calls the tool's execute function. finalizeExecutedToolCall lets hooks replace content, details, error state, or termination.
